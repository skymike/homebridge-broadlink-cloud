# BroadLink Cloud for Homebridge

Private integration for RM MAX remotes stored in BroadLink's EU cloud. Separate from AUX Cloud.

## Features

- Ceiling fans: named speed levels and explicit off, plus an optional momentary light-toggle switch.
- TCL GYKQ-03_1014 AC profile: HomeKit thermostat with Off/Heat/Cool/Auto and 16–30°C targets.
- Actual room temperature and humidity read from the RM MAX in the same room. Stale readings return an error instead of an invented measurement.
- Optional momentary AC presets for full-state commands, including Dry/Fan modes.
- Direct Node.js cloud control; no running Android emulator needed after session setup.

Physical verification: living-room fan speed 1 and Off, and TCL Cool 25°C and Off, all confirmed by the owner. Cloud sensor values 27.13°C / 46.77% matched the app's rounded 27.1°C / 46.8%. Other fan speeds, guest-room fan, light toggle and other AC modes have not been physically tested. The AC encoder matches eleven offline codes generated by the actual Android SDK.

## Requirements and limitations

Node.js 22.18+ or 24, Homebridge 1.8+ or 2, online RM MAX, and a current EU-region account session. Optional email/password settings enable automatic re-login when the saved session expires. Password login is covered by protocol tests but awaits live verification with credentials entered by the owner. The exact configured TCL profile is checked before commands are enabled; other TCL profiles are unsupported.

Fan/AC settings reflect acknowledged commands, not appliance feedback. Fans initially display Off after a restart until a command is acknowledged; this is a display default and does not send an Off command or measure actual fan state. Physical remotes can make the thermostat's last-commanded settings stale. Heating/cooling activity is an estimate from commanded mode, target and measured room temperature, not compressor telemetry. Commanded power starts unknown after restart; select an explicit Off/Heat/Cool/Auto mode before changing target temperature. Cloud failures preserve cached accessories and commands are never automatically retried. Multiple codes per fan button are rejected until their sequence timing is verified.

The RM MAX temperature sensor must be in the same room as the AC. The platform polls every minute; temperature/humidity older than three minutes are unavailable. It does not implement an independent thermostat control loop: the AC regulates itself using its own sensor after receiving the target.

## Setup

Run `npm install --ignore-scripts`, `npm test`, `npm run build`, then `npm pack`. Install the resulting tarball through your Homebridge installation's normal plugin workflow. The package has no additional runtime dependencies.

Store an existing authenticated session outside the plugin and source control, readable only by the Homebridge service account:

```json
{"userId":"YOUR_USER_ID","loginSession":"YOUR_SESSION","familyId":"YOUR_FAMILY_ID"}
```

Session bootstrap currently requires the signed-in BroadLink app; there is no login wizard yet. Use `BroadlinkCloudClient.listDevices()` to obtain remote and hub IDs. Never share raw discovery output: it includes device credentials.

Add to Homebridge's `platforms` array:

```json
{
  "platform": "BroadlinkCloud",
  "name": "BroadLink Cloud",
  "sessionFile": "/var/lib/homebridge/broadlink-session.json",
  "fans": [{
    "name": "Living Room Fan",
    "remoteId": "FAN_REMOTE_ID",
    "hubId": "RM_MAX_ID",
    "exposeLightToggle": true
  }],
  "airConditioners": [{
    "name": "Living Room AC",
    "remoteId": "AC_REMOTE_ID",
    "hubId": "RM_MAX_ID"
  }]
}
```

The session file is reread on each refresh. In Homebridge plugin settings, enter both your BroadLink email and password to enable automatic re-login. Blank fields keep session-only operation. Credentials remain in Homebridge configuration; protect its backups. Renewal preserves the same account and family, atomically replaces the protected session file, and retries read-only discovery once. Failed renewal attempts have a five-minute cooldown; appliance commands are never replayed. Without credentials, replace expired sessions manually. Sessions and saved codes are not placed in accessory caches or logs.

Visible fan button names determine mapping: `Fanoff`, contiguous numeric labels starting at `1`, optional `LightOn/Off`. The tested fans have six levels; the template's internal `on` function actually toggles the light. Light Toggle is a momentary action, not the actual light's on/off state.

Optional `acPresets` entries require `id`, `name`, `remoteId`, `hubId`, `power` (boolean), `temperature` (16–30 integer), `mode` (`auto`, `cool`, `dry`, `fan`, `heat`), `speed` (`auto`, `low`, `medium`, `high`), and `swing` (boolean). These reset to off after triggering and do not indicate physical AC state. Choose either thermostat or presets for each AC remote; configuring both for the same remote is rejected to prevent conflicting assumed state.

## Development

```sh
npm test
npm run check
npm run build
npm pack --dry-run
```

Tests use synthetic fixtures, including credential-free IR patterns generated from synthetic AC settings. Package contents exclude APKs, decompiled sources, downloaded app profiles and account captures. Public application protocol constants are not user credentials. This unofficial integration is not affiliated with BroadLink.
